## Résumé exécutif — l'insight central

Asas Voice n'est pas à *un* pourcentage d'avancement, mais à **trois**, parce que trois
produits différents sont empilés dans le même dépôt :

| Niveau | Ce que ça mesure | Avancement |
|---|---|---|
| 🟢 **Le LOGICIEL** (ça marche ?) | L'app de dictée en elle-même | **~85 %** — quasi-fini, qualité proche production |
| 🟠 **Le PRODUIT DISTRIBUABLE** (installable proprement ?) | Signature, updater, installeur, CI | **~40 %** — buildable mais pas livrable sérieusement |
| 🔴 **Le PRODUIT VENDABLE** (peut-on encaisser ?) | Paiement, licence, site, légal | **~5 %** — quasiment rien n'existe |

**Le plus dur (faire un bon logiciel) est fait. Le reste (le distribuer et le vendre) est un
chantier différent, moins technique, et presque entièrement devant nous.**

### Notes par dimension

| Dimension | Note | Commentaire |
|---|---|---|
| App desktop (fonctionnel) | **8 / 10** | Mûre, cohérente, défensive. Aucun stub. |
| Backend (contexte sidecar local) | **7 / 10** | `/transcribe` niveau prod ; `/postprocess` faible. |
| Qualité / tests | **2 / 10** | **Zéro test** dans tout le dépôt. |
| Packaging / distribution | **4 / 10** | Buildable mais ni signé, ni updater, ni CI. |
| Commercialisation | **~0,5 / 10** | Aucune brique de vente. |

### Flux critique de dictée
`Pressed` → `start()` → `capture_target` (HWND cible, `lib.rs` L364) → `openMicStream` →
`startRecording` (MediaRecorder webm/opus) → orbe `listening`. **Relâchement** → `stop()` →
blob → `postAudioForTranscription` (POST /transcribe, timeout 65 s `transcribeClient.ts` L39)
→ post-traitement local → Claude optionnel → `history.add` → `pasteText` sinon `copyText` →
orbe `confirmed` → `idle` après 760 ms.

### Points de fragilité
- **Dépendance dure au sidecar** : échec de lancement signalé seulement en `eprintln!`
  (`lib.rs` L167,197) + point « Hors ligne ». Pas de vrai bandeau UI « backend introuvable ».
- **Collage = Windows only** : `restore_focus`/`is_foreground` no-op hors Windows (`lib.rs` L353-361).
- **Fiabilité focus** : malgré 10 tentatives + `AttachThreadInput`, le verrou premier-plan Windows
  peut échouer sur certaines apps → repli presse-papier (bien géré, mais fragilité intrinsèque).
- **Pas de durée max d'enregistrement** → une dictée très longue dépasse la limite backend 60 s.
- **MediaRecorder / AudioContext absents** non couverts explicitement (`recorder.ts` L9-12).
- **Export** télécharge sans dialogue de destination.

### Sécurité / intégration Rust (solide)
- Clés API dans le **coffre Windows** (`com.asasvoice.app`), le renderer **ne peut jamais relire**
  la clé (`config.ts` L5-8). Jamais en localStorage ni webview.
- Sidecar avec **Job Object « kill-on-close »** anti-orphelin (`lib.rs` L81-124) — qualité rare.
- CSP verrouillée `connect-src 'self' http://127.0.0.1:4321` ; single-instance ; capabilities
  scindées main/orb.

## 2. Backend — 7/10 (Fastify, sidecar local)

### Routes
- `GET /health` (`server.ts:64`) — renvoie toujours `ok`, sans introspection.
- `GET /config` (`server.ts:71`) — expose `hasKey` / `hasAnthropicKey` (booléens, jamais les clés).
- `POST /transcribe` (`routes/transcribe.ts:156`) — cœur produit, multipart audio → texte.
- `POST /postprocess` (`routes/postprocess.ts:23`) — reformulation via Claude.

### Points forts
- **`/transcribe` niveau production** : `handleUpstreamError` (`transcribe.ts:70-149`) distingue
  timeout→504, connexion→502, clé invalide→502, **audio muet code 3310 → 422**, modèle invalide→502.
  Validation d'entrée exhaustive (25 Mo, MIME whitelist, buffer vide rejeté, vocabulaire borné 100 termes).
- **Sécurité** : clé serveur-only, anti-DNS-rebinding (`server.ts:25-38`), CORS strict
  (`server.ts:40-48`), en-tête custom `X-Asas-Client`, bind `127.0.0.1` only. `.env` gitignoré/non-tracké.
- **Context biasing** propre (`transcribe.ts:201-209`, `stt.ts:50,57`).

### Faiblesses
- 🔴 **`/postprocess` = maillon faible** : appel `client.messages.create` (`postprocess.ts:49-54`)
  **sans try/catch, sans timeout, sans borne de taille d'entrée** → 500 non structuré hors contrat `ApiError`.
- **Quota / HTTP 429 non mappé** spécifiquement (tombe dans le fourre-tout 502, `transcribe.ts:138-142`),
  pas de `Retry-After`.
- **Validation d'en-tête incomplète sur `/postprocess`** : exige la *présence* de `x-asas-client`
  mais pas sa *valeur* (`postprocess.ts:26-32`), contrairement à `/transcribe`.
- **Aucun graceful shutdown** (`SIGTERM`/`SIGINT` → `app.close()` absent).
- **`/health` trompeur** (toujours `ok`), inutilisable comme readiness probe.
- **Aucun rate-limiting, aucun retry, aucun test.**
- **Modèle post-traitement daté** : `claude-sonnet-4-6` (`postprocess.ts:5`) — à moderniser.
- **Stubs** : fournisseurs `openrouter` / `deepinfra` lèvent `ProviderNotImplementedError` (`stt.ts:79-81`).
- **Versionnement** : `package.json` backend `version: "0.0.0"`.

## 3. Packaging / distribution — 4/10

- ✅ **Build fonctionnel** : `externalBin: ["binaries/asas-voice-backend"]`, sidecar réellement lancé
  par `spawn_backend()` (`lib.rs`) avec injection des clés depuis le trousseau. Chaîne
  `build-sidecar.mjs` → tsup → `@yao-pkg/pkg`.
- 🔴 **Pas de signature Authenticode** : aucune section `bundle.windows`, aucun certificat dans le dépôt
  → **SmartScreen bloquera** à l'installation. Bloquant absolu pour un produit payant.
- 🔴 **Pas d'auto-updater** : `tauri-plugin-updater` absent de `Cargo.toml`, aucune section
  `plugins.updater`, aucune permission updater → impossible de pousser un correctif aux clients.
- 🔴 **Artefacts périmés / incohérents** : installeurs du 15 juin sans le sidecar actuel, résidus
  « Voxa », versions désalignées (`0.0.0` racine vs `0.1.0`).
- 🟠 **Aucune CI/CD** (`.github/` absent) → builds 100 % manuels.
- 🟠 **Installeur non personnalisé** : MSI **en-US** pour un public FR, pas d'EULA, `webviewInstallMode` non défini.
- 🟡 **Multi-OS théorique** : icônes `.icns`/`.ico` présentes, mais collage/focus `#[cfg(windows)]`
  → **inopérant sur macOS/Linux**. Cibler **Windows seul** pour la v1.
- 🟡 **Scripts legacy à ne pas expédier** : `start-backend.cmd` (chemin `dist/server.js` obsolète),
  `Lancer-Asas-Voice.vbs` (lance l'exe de dev).

## 4. Commercialisation — ~0,5/10

- **Modèle actuel = BYOK intégral** : l'utilisateur fournit **sa propre clé Mistral** (`Onboarding.tsx`,
  bouton → `console.mistral.ai/api-keys`). Tout tourne en local. L'éditeur n'a **aucun coût variable**.
  - ✅ Marge ~100 %, aucun risque de surconsommation.
  - ⚠️ Friction énorme pour le grand public (créer un compte dev Mistral + copier une clé).
- **Infrastructure de vente : AUCUNE** (confirmé par recherche exhaustive) — pas de compte, pas de
  licence/activation, pas de paiement (Stripe/Paddle/Lemon Squeezy), pas de quota, pas de site.
  Le header `X-Asas-Client` est une protection CORS, **pas** une licence.
- **À construire** : statut juridique, paiement (Merchant of Record : **Lemon Squeezy**/Paddle → gèrent
  la TVA), licence + activation (Keygen.sh ou LS License API), écran d'activation dans l'app, site +
  portail client, CGV + politique de confidentialité RGPD + mentions légales.
- **Deux chemins** :
  - **(a) Licence perpétuelle BYOK** — compatible immédiatement avec l'archi actuelle, ~1-2 semaines,
    marge 100 %, cible pros/technophiles. **← Recommandé pour démarrer.**
  - **(b) SaaS abonnement** — nécessite backend cloud + clé côté serveur + comptes + quotas ; plusieurs
    mois ; charge RGPD accrue (la voix transite par tes serveurs). **← Étape 2, après validation du marché.**
- 💡 **Argument RGPD vendeur** avec (a) : « la voix ne quitte pas votre appareil ».

## Roadmap de commercialisation (rappel — hors périmètre finalisation logiciel)

- **Phase A** — Figer & durcir l'existant (WIP committé, `/postprocess`, tests, rebuild propre).
- **Phase B** — Rendre distribuable (certificat EV, updater Tauri, CI/CD, installeur FR).
- **Phase C** — Rendre vendable (licence perpétuelle BYOK, Lemon Squeezy, activation, landing).
- **Phase D** — Légal (micro-entreprise, CGV, confidentialité RGPD, mentions légales).
- **Phase E** — SaaS (backend cloud, clé serveur, comptes, quotas) — plus tard.

Estimation : **~4-6 semaines** de travail (hors délais admin certificat/structure) de l'état actuel
à « je peux vendre une licence sur mon site ».
